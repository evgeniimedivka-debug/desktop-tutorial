# Автопубликация Milis Decor — Telegram + Instagram

Пакет для настройки шага «публикация» в контент-заводе Milis Decor
(VPS 31.130.131.58, n8n + NocoDB). Ревью и одобрение контента остаются
ручными — автоматизация подхватывает запись только после того, как флаг
одобрения проставлен.

Собрано в сессии Claude Code без прямого доступа к VPS/n8n/NocoDB/Meta —
это конфигурация и раннбук для владельца/интегратора, готовые к импорту.
Единственное, что проверено вживую из этой сессии: бот @miliscontentbot
уже администратор канала @MilisDecor с правом `can_post_messages: true`
(chat_id канала: `-1003914664264`) — постить в канал можно сразу, без
дополнительной настройки на стороне Telegram.

## Файлы

| Файл | Что внутри |
|---|---|
| `nocodb-schema.md` | Поля, которые нужно добавить в таблицу «Ролики», и статусная модель |
| `instagram-setup-runbook.md` | Пошагово: FB Business Manager → Page → IG Business-аккаунт → App → долгоживущий токен (с нуля, т.к. сейчас ничего не привязано) |
| `n8n-workflows/CF-07-approve-via-bot.json` | Обработка команды/кнопки «Одобрить» от владельца в @miliscontentbot → проставляет флаг в NocoDB |
| `n8n-workflows/CF-08-publish-telegram.json` | Публикация одобренной записи в канал @MilisDecor (sendPhoto/sendVideo) |
| `n8n-workflows/CF-09-publish-instagram.json` | Публикация одобренной записи в Instagram (фото и Reels) через Graph API |

## Архитектура (коротко)

```
Владелец пишет боту @miliscontentbot команду/жмёт кнопку "Одобрить"
        │
        ▼
CF-07 (Telegram Trigger) ── NocoDB: Одобрено=true, Статус="одобрено"
        │
        ▼  (NocoDB webhook на изменение Статус = "одобрено")
CF-08 (Telegram publish) ── sendPhoto/sendVideo в @MilisDecor
        │                    NocoDB: Статус="опубликовано в Telegram"
        ▼  (NocoDB webhook на этот статус)
CF-09 (Instagram publish) ── Graph API: создать медиа → опубликовать
                              NocoDB: Статус="опубликовано в Instagram"
```

Каждый шаг публикации проверяет текущий статус записи перед действием —
это защита от дублей при повторном срабатывании webhook'а.

## Что нужно от владельца, прежде чем включать

1. **Instagram — начинаем с нуля** (ваш ответ: FB Business Manager и
   привязанный IG Business-аккаунт отсутствуют). Порядок — в
   `instagram-setup-runbook.md`. Это шаги в личном кабинете Meta,
   их не может сделать автоматизация — нужны ваши логин/аккаунт.
2. **Одобрение — команда/кнопка боту @miliscontentbot** (ваш ответ).
   В CF-07 заложено два варианта на выбор:
   - инлайн-кнопка «✅ Одобрить» под каждым сообщением с готовым роликом/постом
     (бот уже шлёт их вам в личку — кнопку нужно добавить в тот же шаг отправки,
     в существующий workflow CF-01…05, не здесь);
   - текстовая команда `/approve <ID записи>`.
   Рекомендация: кнопка — не нужно вручную вводить ID, меньше риска ошибиться записью.
3. **Секрет для NocoDB→n8n webhook** — по аналогии с уже существующим
   `x-cf-secret` для `/webhook/cf/render`, чтобы публикацию нельзя было
   дёрнуть кем угодно.
4. **Токен бота уже был в открытом виде в постановке задачи** — если
   переписка, где он фигурировал, не защищена так же строго, как сам
   VPS, стоит перевыпустить токен через @BotFather (`/revoke`) и
   обновить его в n8n-credentials. Это не блокирует настройку, просто
   гигиена секретов.

## Что не сделано в этой сессии и почему

Прямого доступа к n8n/NocoDB/Meta Business Suite из этой облачной сессии
нет (нет учётных данных, VPS не в scope). Workflow-JSON ниже собраны
вручную по актуальному API n8n и готовы к импорту через n8n UI → Import
from File. После импорта: заполнить n8n-credentials (Telegram Bot,
NocoDB API token, Instagram Graph API token) и включить workflow.
