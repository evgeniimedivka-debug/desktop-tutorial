# NocoDB — таблица «Ролики» (как развёрнуто по факту)

База: «Контент-завод Milis Decor» (`pgcrh775xcev3n6`), таблица «Ролики»
(`mbv0dd92dx4irfp`).

Важно: в таблице уже был рабочий статус-пайплайн (`Статус`,
single select) с значениями `Идея → Сценарий → Готов к рендеру →
Рендер → На согласовании → На доработку → Одобрено → Опубликовано →
Ошибка рендера`, который используют CF-01…04. Новая схема **переиспользует
это же поле**, а не заводит отдельное «Статус публикации» — чтобы не
плодить два параллельных статуса на одну запись.

## Добавленные поля (созданы через API в этой сессии)

| Поле | Тип | id колонки | Назначение |
|---|---|---|---|
| `Одобрено владельцем` | Checkbox | `cl2spdfdcmccvp7` | Единственный ключ запуска публикации. Ставит владелец в Gallery View «Согласование». |
| `IG: Опубликовано` | Checkbox | `czed6flize5x25a` | Отдельный флаг для Instagram — публикация в TG и IG больше не завязаны на одно значение `Статус`, т.к. Instagram может быть не нужен для всех записей. |
| `IG media id` | SingleLineText | `cgqiejzwmgf3w6h` | id опубликованного медиа в Instagram, для аудита. |
| `TG message id` | SingleLineText | `cmcfl0sc2f6vb05` | id сообщения в канале @MilisDecor. |

В мультиселект `Канал` (id `c8epzowukhu3yon`) добавлена опция
**`Instagram`** (её не было — раньше были только Telegram/VK
Клипы/YouTube Shorts/Rutube/Дзен/Pinterest/Avito).

## Как теперь используется `Статус`

- `На согласовании` — запись ждёт решения владельца (ставит CF-02).
- `Одобрено` — CF-08 ставит это значение сразу после того, как увидел
  `Одобрено владельцем = true`, перед отправкой в Telegram.
- `Опубликовано` — CF-08 ставит после успешной отправки в Telegram
  канал (`sendVideo`). Это по-прежнему означает «в Telegram», как и
  раньше в CF-04 — семантику поля не меняли, чтобы не сломать то, что
  на него завязано.
- Instagram отслеживается отдельно через `IG: Опубликовано` — запись
  может быть `Статус=Опубликовано` (в Telegram) и одновременно
  `IG: Опубликовано=false`, если Instagram ещё не готов технически или
  канал `Instagram` не выбран для этой записи.

## Защита от дублей

- CF-08 проверяет `Одобрено владельцем=true` **и** `Статус=На
  согласовании` перед тем, как что-то публиковать — если статус уже
  ушёл дальше (например, webhook сработал повторно), запись
  пропускается.
- CF-09 проверяет `Одобрено владельцем=true`, `IG: Опубликовано≠true` и
  `Канал` содержит `Instagram`.

## Gallery View «Согласование» (создан через API)

- id вида: `vw0211cpf1d3r800`.
- Filter: `Статус = На согласовании`.
- Владелец открывает этот вид, видит превью (video_url), хук, рубрику,
  аудиторию — и ставит чекбокс `Одобрено владельцем`. Больше ничего
  делать не нужно, ни бота, ни переписки.

## Webhook в NocoDB → n8n (единственный шаг, оставшийся вручную)

NocoDB 2026.09.0 отключила создание webhook через REST API (`hook
version is deprecated`), новый API — только Enterprise. Поэтому это —
единственная часть, которую нужно сделать в UI:

1. Таблица «Ролики» → Details → **Webhooks** → **New Webhook**.
2. Event: **After** → Operation: **Update**.
3. Condition: `Одобрено владельцем` = `true`.
4. URL: `https://n8n.31-130-131-58.sslip.io/webhook/cf/publish-telegram`.
5. Header `x-cf-secret` = значение, уже используемое для
   `/webhook/cf/render` (в CF-08 сверяется с `$env.CF_SECRET` — тем же,
   что и во всей остальной семье CF-02…CF-06).
6. Для Instagram — аналогично, но URL
   `.../webhook/cf/publish-instagram`, включать после готовности
   `IG_USER_ID`/`IG_ACCESS_TOKEN` (см. `instagram-setup-runbook.md`) и
   активации CF-09.
